Bayesian Probability Engine

6-engine continuous rolling probability field for 0DTE options. 200 nodes, 8 domains, 5 mathematical collapse strategies, 1 production signal.

1. System Overview

The engine ingests ~70 market context fields every tick and routes them through six mathematical collapse strategies. Each strategy computes a posterior probability independently. The production V6 meta-ensemble stacks all five into a single composite signal that feeds the state machine.

2. The Mathematics

V1 — Deterministic Logit-Space Collapse BASE

The foundational engine. 200 ProbNodes organized into 8 domain workers, each maintaining a continuous posterior via EMA smoothing with a 15-minute half-life. Node posteriors are combined in logit space — the only mathematically correct way to combine independent probability estimates.

logit(p) = ln(p / (1 − p)) // map [0,1] → ℝ inv_logit(x) = 1 / (1 + e⁻ˣ) // map ℝ → [0,1] logit_effect_i = logit(posterior_i) − logit(base_rate_i) domain_score = inv_logit(Σᵢ wᵢ · logit_effect_i) // per domain composite = Σ_d importance_d · domain_score_d // weighted across domains // EMA continuous update: α = 1 − exp(−Δt · ln(2) / half_life) // half_life = 900s (15 min) posterior_new = α · observed + (1 − α) · posterior_old // Regime multipliers scale each node's effect: effective_logit = logit_effect × regime_mult × gex_mult

V2 — Monte Carlo Regime Prediction MC

Extends V1 with a forward-looking Markov chain Monte Carlo regime predictor. A 6×6 transition matrix (CHOP, TREND_UP, TREND_DOWN, EXPANSION, COMPRESSION, UNKNOWN) is sampled 500 times to predict the next 15-minute regime. An attractor-repeller field assigns directional forces to live nodes.

// Markov regime transition (6×6 matrix): P(regime_{t+1} | regime_t) = transition_matrix[current][next] // Monte Carlo: 500 simulations, 1-step horizon forecast = Counter(sample_next_regime(current) for _ in range(500)) regime_probs = {r: count/500 for r, count in forecast.items()} // Attractor-repeller field: force_i = direction_i × posterior_i × weight_i field_potential = tanh(Σᵢ force_i / √n) // ∈ [-1, +1] // V9 Hybrid Blend: composite = 0.40 · domain_score + 0.35 · mc_adjusted + 0.25 · field_score

V3 — James-Stein Factorized Shrinkage SHRINK

Applies Stein's paradox: when estimating 3+ parameters simultaneously, shrinking each toward a grand mean always reduces total MSE. Four independent factors (regime, GEX, time-of-day, VIX bucket) each contribute a shrunk effect.

// Shrinkage per factor: shrunk_effect = raw_effect × n / (n + k) // k = min_support // 4 factors: Regime × GEX × ToD × VIX factorized_logit = Σ_f shrunk_effect_f(global_mean) factorized_posterior = inv_logit(factorized_logit) // Blend with base: composite = 0.60 · factorized + 0.40 · v1_base

V4 — Inverse-Variance Adaptive Ensemble STACK

Stacks V1, V2, V3 using the Bates-Granger combination framework. Static priors (0.35/0.35/0.30) are blended 50/50 with adaptive inverse-distance weights. A confidence discount fires when engines disagree.

// Agreement metric: σ = std_dev(v1_post, v2_post, v3_post) agreement = 1 − min(σ / 0.25, 1) // Adaptive weighting (inverse distance from mean): inv_dist_i = 1 / max(|p_i − mean|, 0.01) adaptive_w_i = inv_dist_i / Σ inv_dist // Blend: w_i = 0.5 · static_w_i + 0.5 · adaptive_w_i composite = Σ w_i · p_i // Confidence discount when engines disagree: if agreement < 0.7: discount = 0.5 + 0.5 · agreement composite = 0.5 + (composite − 0.5) · discount

V5 — Information-Theoretic Entropy Weighting INFO

Lets the data decide which nodes matter. Measures each node's actual information contribution via Shannon entropy and KL divergence, then MDL-prunes nodes whose signal doesn't justify their complexity cost. Rényi entropy guards against single-node domination.

// Shannon entropy (node uncertainty): H(p) = −p · log₂(p) − (1−p) · log₂(1−p) // max 1 bit at p=0.5 // KL divergence (information gained per tick): KL(posterior ‖ prior) = p·ln(p/q) + (1−p)·ln((1−p)/(1−q)) // EMA-smoothed KL → sustained info contributors: KL_ema = 0.12 · KL_new + 0.88 · KL_ema_old // Info weight per node: info_weight = KL_ema × (1 − mean_entropy) // high info + low noise // MDL pruning (minimum active floor = 20): complexity_penalty = 0.5 · log₂(n_ticks) / n_ticks keep node if KL_ema > penalty OR active_count < 20 // Rényi effective sample size: H₂ = (1/(1−α)) · log₂(Σ wᵢᵅ) // α = 2 ESS = 2^H₂ // floor = 3.0

V6 — Meta-Ensemble Production Signal PROD

The production signal. Runs all five engines per tick and collapses them with tail-agreement bonuses — because consensus matters most when engines agree on direction in the tails (high or low probability), which is where 0DTE money is made.

// Pairwise agreement (5×5 matrix): agreement[i][j] = 1 − |p_i − p_j| // Adaptive weights (median-distance): w_i = 0.5 · static_w_i + 0.5 · (1/dist_from_median) / Σ(1/dist) // Tail-agreement bonus: if ≥4 engines above 0.65 OR below 0.35: logit_composite *= (1 + 0.15) // amplify strong consensus if all 5 agree: logit_composite *= (1 + 0.25) // Dispersion discount: if agreement < 0.6: composite = 0.5 + (composite − 0.5) × (0.4 + 0.6 · agreement)

3. Why It's Solid

Every mathematical choice has a provable reason. No hand-waving — each technique either has a formal optimality guarantee or an empirical track record in the statistics literature.

1
Logit-space combination is the only correct way to combine probabilities.

Jeffrey's rule (1946): multiplying likelihood ratios in log-space is equivalent to additive combination in logit-space. This is the ONLY operation that respects the [0,1] constraint and preserves calibration. Averaging raw probabilities is provably miscalibrated — two 90% estimates averaged give 90%, but the logit combination gives 0.95 (which is correct: two independent pieces of evidence both saying 90% should be more certain than either alone).

2
EMA with half-life creates a continuous rolling function, not binary snapshots.

The exponential moving average with α = 1 − exp(−Δt·ln(2)/τ) is the unique linear filter that is (a) causal (uses only past data), (b) continuous in time (works for irregular tick spacing), and (c) has a well-defined memory horizon (half-life τ = 900s = 15 min). The posterior at any moment is a weighted integral of all past observations, with recent observations weighted exponentially more.

3
James-Stein shrinkage provably dominates MLE for 3+ parameters.

Stein's paradox (1956, proved by James & Stein): when estimating ≥3 parameters simultaneously under squared-error loss, shrinking every estimate toward the grand mean ALWAYS has lower total MSE than the individual MLEs. This is not approximate — it's a strict domination result. With 200 nodes across 4 factor dimensions, shrinkage is mathematically guaranteed to improve total estimation quality.

4
MDL pruning has information-theoretic optimality guarantees.

Rissanen's Minimum Description Length principle (1978): the best model minimizes the total code length = model description + data given model. Barron, Rissanen & Yu (1998) prove MDL achieves minimax-optimal rates for model selection. When V5 prunes nodes whose KL information doesn't exceed the complexity penalty, it's provably selecting the model complexity that maximizes predictive compression.

5
KL divergence is the unique measure satisfying the chain rule of information.

Cover & Thomas (2006): among all non-negative functions that vanish when two distributions are identical, the KL divergence is the ONLY one satisfying D(p‖q) = D(p₁‖q₁) + D(p₂‖q₂|p₁=q₁). This means information gains from different nodes decompose additively — exactly what we need for per-node information scoring.

6
Inverse-variance ensemble stacking minimizes MSE.

Bates & Granger (1969): given forecasters with known error variances, inverse-variance weighting is the minimum-MSE combination. The adaptive blend with static priors is a regularized version that's robust when variance estimates are noisy (early ticks). The 50/50 blend between static and adaptive is a bias-variance tradeoff that converges to pure adaptive as tick count grows.

7
Each engine fails in a DIFFERENT regime — the meta-ensemble is robust across all states.

V1 fails on regime transitions (static weights lag). V2 fails on stable regimes (MC noise adds no signal). V3 fails on sparse factor buckets (shrinkage collapses to prior). V4 fails when V1-V3 are correlated (no new information). V5 fails on the first 15 ticks (not enough history for entropy estimates). By combining orthogonal failure modes, V6 has no single-regime vulnerability.

4. Node Architecture

200 ProbNodes across 8 domains. Each node carries a base rate, regime multipliers, GEX multipliers, a half-life, a priority (1-5), a verification verdict, and a strategy role. Nodes are weighted by a reliability function that implements partial pooling.

// Reliability (partial pooling with observation count): reliability(n) = n / (n + min_support) // min_support = 10 default // Effective weight per node: effective_weight = reliability × (priority / 5) × verdict_weight // verdict_weight: TRUE=1.0, PARTIALLY_TRUE=0.75, UNVERIFIED=0.5, FALSE=0.1

Node lifecycle: A node starts inactive (_is_live = False). On its first observation, it goes live and begins EMA-decaying. When its required market context fields are missing, it remains at its base rate — no hallucinated data. Priority 1-5 scales the weight (priority/5), and the verification verdict further scales it (TRUE = 1.0, FALSE = 0.1). The reliability function n/(n+10) means a node with 1 observation has 9% of its full weight; at 10 observations it's at 50%; at 100 it's at 91%. This implements partial pooling — new nodes barely influence the composite until they've accumulated evidence.

5. Confidence Routing

The posterior doesn't just estimate direction — it controls how much capital to risk. Four tiers route from the posterior through Kelly sizing and an EV gate before any execution.

Posterior Range Uncertainty Tier Action
< 0.12 or > 0.88 Low (<24%) FULL Full position. Kelly-optimal sizing.
0.12 – 0.22 or 0.78 – 0.88 Moderate HALF Half-size. Still fires if EV > 0.
0.22 – 0.35 or 0.65 – 0.78 Elevated QUARTER Quarter-size. Informational only for high-conviction overrides.
0.35 – 0.65 High (>70%) PAPER No live execution. Log for tracking only.

Kelly Criterion

// Kelly optimal fraction: f* = p − (1 − p) / R // R = avg_win / avg_loss f_actual = f* × 0.25 // fractional Kelly (1/4) // Example: p=0.62, avg_win=$2.40, avg_loss=$1.20, R=2.0 f* = 0.62 − 0.38/2.0 = 0.43 // 43% Kelly f_actual = 0.43 × 0.25 = 0.1075 // risk 10.75% of bankroll

// Expected Value gate — fire only if positive: EV = p̂ · W̄ − (1 − p̂) · L̄ − c // c = round-trip cost ($0.20) // Must clear EV > 0 to execute. No fee first, fees layered after.

6. Failure Modes & Graceful Degradation

Every engine degrades gracefully when data sources are unavailable. No hallucinated data — missing fields leave nodes at their base rate.

Engine Primary Failure Mode Degradation Behavior
V1 Regime transitions (static weights lag by ~1 half-life) Nodes with missing required_fields stay at base rate. Domain with 0 live nodes contributes nothing.
V2 Stable regimes (MC noise adds no signal; wastes compute) Falls back to V1 base posterior if MC forecast is uniform. Attractor field → 0 when no live nodes contribute directional force.
V3 Sparse factor buckets (shrinkage collapses everything to grand mean = 0.5) With n=0, shrinkage formula gives weight=0 → that factor contributes nothing. Falls back to the 40% V1 base component.
V4 Correlated engines (V1-V3 agree → no diversity benefit) Agreement → 1.0, no discount applied. Adaptive weights → equal (all same distance from mean). Degenerates to a simple average.
V5 First 15 ticks (not enough history for entropy/KL estimates) MDL pruning disabled for ticks < 15. All 200 nodes active. Equivalent to V1 with uniform info-weights.
V6 Complete data loss (no market context fields available) All nodes at base rate → all engines ≈ 0.5 → composite ≈ 0.5 → PAPER tier → no execution. Fail-safe.
The invariant: Under complete data loss, every engine converges to a posterior near 0.5 (maximum uncertainty), which routes to the PAPER tier. The system never executes on no data — it fails closed. Under partial data loss, the reliability weighting (n/(n+10)) ensures nodes with zero observations contribute zero weight. The system degrades proportionally to the fraction of missing data, never catastrophically.
